Related to #261 and the discussion on #382. This draft does not close #261.

#### What does this implement/fix? Explain your changes.

Integrate Carlo Nicolini's online portfolio framework into skfolio's estimator and Portfolio interfaces. The three public estimators delegate to shared kernels: `ExponentiatedGradient` and `AdaGrad` use the OCO engine with different mirror maps; `OnlineMovingAverageReversion` uses the mean-reversion family. The broader family configurations remain internal.

Implemented:
- `fit` resets; `partial_fit` continues and processes blocks causally. After observing period t, `weights_` targets t+1.
- Shared OMD/FTRL machinery, predictors and supported native constrained mirror objectives. OLMAR's price window includes the current price.
- Portfolio handles holdings drift, execution costs and wealth. Turnover uses actual supplied holdings; warmup intermediate targets are not trades.
- Shared weight, budget and group/asset constraint expressions; optional causal priors with row-aligned metadata and `max_variance`.
- Explicit public constructors, cloning and online parameter search, one-period evaluation, documentation and a runnable example.
- Static and dynamic regret, averaging/windowed curves and plotting; hindsight benchmark helpers remain internal. Online losses use Portfolio execution on a copy, while comparators are gross of costs.
- Carlo's algorithm tests, adapted where execution ownership or update semantics changed. Independent references check EG, AdaGrad, the adaptive composite potential, and interior OLMAR/PAMR updates.

Source: [Carlo's pinned implementation](https://github.com/CarloNicolini/skfolio/tree/c1bd1f168cf7d660c81f74710aadd9941e64a2c7). Source headers and commit attribution are retained. `integration/issue_261/PORT_INVENTORY.json` records source hashes, destinations and adaptations. This is a substantial framework port; much of the diff is source machinery and its tests.

#### Does your contribution introduce a new dependency? If yes, which one?

No new runtime dependency. Autograd is added to development extras for gradient verification; the public estimators work without it.

#### What should a reviewer concentrate their feedback on?

1. The three concrete public estimators over the configurable private families, including names and FTRL/OMD defaults.
2. Native constrained geometry, adaptive-state ordering and the corrected OLMAR timing.
3. Turnover anchors and prior availability at the first execution decision.
4. Whether the broader private objective/family catalogue should remain in this PR or be split into a subsequent port.

Suggested review order: mirror maps/projector/OCO engine; shared lifecycle and family adapters; Portfolio evaluation and shared constraints; public constructors and independent algorithm tests.

#### Any other comments?

The branch is refreshed against upstream v1.8.1. Local validation: 10,845 tests and source doctests passed with no skips, including 672 online tests. Ruff lint/format, type checking and docstring checks pass. The Sphinx build succeeds with warnings. GitHub CI is still required after publication.

Deferred: dynamic universes, automatic recovery, larger evaluation windows, factor constraints and unregistered/Tsallis constrained geometries. RMR remains internal with unbounded history. Numerical or prior failures require a fresh fit.
